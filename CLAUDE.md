# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What is mktba

**mktba** — open-source исламская wiki-платформа, hard fork WikiWeaver. Контент организован как иерархическое дерево статей, каждая содержит параграфы, а каждый параграф — одно или несколько «мнений» (Opinion), привязанных к одной или нескольким школам исламского права (мазхабам). Поддерживаются 4 канонические суннитские школы (Hanafi, Maliki, Shafi'i, Hanbali) плюс произвольные кастомные школы per-article. Админ-панель (`/admin`, доступна только по прямому URL) управляет всем контентом.

UI — только на русском. Целевой домен — `mktba.ru`.

## Commands

### Backend (run from repo root)
```bash
docker compose up -d postgres
dotnet build Mktba.sln            # plain `dotnet build` fails with MSB1011 (docker-compose.dcproj)
dotnet test Mktba.sln             # needs the compose `postgres`: the search tests create and drop their own databases
dotnet run --project Mktba.Api    # :5172, Development: connects to the compose `postgres` DB out of the box and migrates it
dotnet run --project Mktba.Api -- --migrate   # apply migrations + system schools and exit (the only way outside Development)
```
Machine-specific settings go in the gitignored `Mktba.Api/appsettings.local.json` (template: `appsettings.local.example.json`); it overrides `appsettings.{Environment}.json`, while user secrets and env vars override it.

```bash
npm install
npm run dev       # react-router dev (Vite + SSR) on :5173
npm run build     # tsc -b && react-router build → build/client, build/server
npm run size      # after build: JS budget of the /:slug article page first load (scripts/check-bundle-size.mjs)

```

## Architecture

Clean DDD layering — each layer depends only on layers below it:

```
Mktba.Domain          → pure entities, no external dependencies
Mktba.Application     → services, DTOs, AutoMapper profiles
Mktba.Infrastructure  → EF Core (PostgreSQL), repositories, Unit of Work, seeders
Mktba.Api      → ASP.NET Core 8 Minimal API, JWT auth, CORS, Swagger
mktba.react           → React 19 + TypeScript, React Router v7 framework mode (SSR), React Query v5, Tailwind CSS v4, Vite
```

**Key domain concepts:**
- `Article` contains ordered `Paragraph`s (slot).
- `Article.Slug` — URL segment: the article lives at `/{slug}` directly under the root (O-02, #53; owner decision: no `/wiki/` prefix), transliterated from the title or set by hand; unique per `Locale` together with old slugs (index `(Locale, Slug)` on both tables). A changed slug leaves an `ArticleSlugRedirect` (carrying the article's locale); an old slug, the old `/article/{slug}` and `/article/{id}` URLs (and a bare `/{id}`) answer 301 to `/{slug}`, keeping the query. Reserved first segments — `ArticleSlugRules.Reserved` (`admin`, `api`, `article`, `articles`, `assets`, `authors`, `feedback`, `login`, `search`, `sitemaps`, `tags` and the locale codes), mirrored by `RESERVED_ARTICLE_SLUGS` in `src/shared/slug.ts` — are refused as a hand-set slug (`article_slug_reserved`) and skipped by the generator (`search` → `search-2`, the fallback `article` → `article-2`); a name with a dot (`robots.txt`, `sitemap.xml`, static files) is never a valid slug. A new top-level route must add its segment to both lists and move any article already there (migration `MoveArticlesOffReservedSlugs` did so once: `{slug}-2`…, old slug kept as a redirect; `AddTags` the same for `tags`). Profile slugs live under `/authors/` and tag slugs under `/tags/`; neither is limited by the list. Transliteration lives in `ArticleSlugRules` (C#), the `AddArticleSlugs` migration backfill (SQL, copied into the `AddTags` backfill) and `src/shared/slug.ts` (editor prefill) — keep them identical. User profile slugs reuse the same two functions with the fallback word `author`, tag slugs with `tag`.
- `Article.Locale` / `TranslationGroupId` (M-09, #27) — D6: a translation is a separate article per language. `Locale` is a short code from `Locales.Supported` (`Mktba.Domain/Entities/Locales.cs`, the one list; default `ru`, anything else → `locale_unsupported`), set on create and never changed. Articles sharing a `TranslationGroupId` are translations of each other, at most one per locale (unique index); a new article starts its own group. `GET /articles/by-slug/{slug}/content?locale=` defaults to `ru`. Revision snapshots do not carry the locale (it cannot change). School names: `School.Name`/`ShortName` are Russian, other languages live in `SchoolTranslation(SchoolId, Locale, Name, ShortName)` (system schools seeded with `en`; not exposed in the API yet, I-07 #111). Tags carry their own `Locale` (M-06, #70), so an article only ever carries tags of its language. English UI/routes are Stage 5 (epic 9).
- Each `Paragraph` holds one or more `Opinion`s; one `Opinion` is marked default (fallback when user's mazhab has no specific opinion).
- `Opinion` ↔ `School` is M:N through `OpinionSchool` join.
- A plain paragraph (exactly one `Opinion`) is common to all schools and has no school links: every write path (`/paragraph`, `/articles/content`, `/articles/{id}/content`) rejects school ids on it with `paragraph_plain_schools_not_allowed`, and the editor offers school selection only in a block with two or more opinions (a block left with one non-empty opinion is saved as a plain paragraph, without school ids). School links belong to versioned paragraphs (two or more opinions).
- `School` — 4 канонические (`IsSystem=true`) + кастомные per-article (`ArticleScopeId` nullable FK).
- `Tag` / `ArticleTag` (M-06, #70): a tag is an entity of one language — `Locale`, `Name` (≤ 50, trimmed, white space collapsed, no comma or control characters), `NormalizedName` (lower case, ё folded to е; unique per locale with the name, so «Фикх» and «фикх» are one tag) and `Slug` (`ArticleSlugRules` with the fallback word `tag`, `-2`, `-3` on a collision; unique per locale). `ArticleTag(ArticleId, TagId, Order)` puts it on an article, at most 16 per article. The content DTOs keep `tags: string[]` (full replace, names): a save resolves each name to the tag of the article's locale with that key and creates the missing ones (`ArticleTagAssigner`, rules in `TagRules`; codes `tag_name_*`, `article_too_many_tags`); reads also give `tagLinks: [{ name, slug }]` for links to `/tags/{slug}`. The old comma-separated column stays as `Article.TagsSearchText` (column `"Articles"."Tags"`), the search copy the generated `SearchVector` reads, written only together with the links — never read for anything else. Migration `AddTags` backfilled the links from it. Admins rename a tag (`PUT /tags/{id}`: a name another tag has → `tag_name_taken`, merge instead; a changed slug is not kept, the old page answers 404) and merge one into another of the same language (`POST /tags/{id}/merge`: the articles carry the remaining tag at the same place, the merged one is deleted); neither writes a revision nor changes `UpdatedAt`. A tag no article carries any more stays in the directory (admin list, count 0) until merged; its page answers 404.
- `Source` / `OpinionSource` (M-07, #71): a `Source` is an entry of one shared directory — `Kind` (`Book`, `HadithCollection`, `Quran`, `Other`; stored by name), `Title` (≤ 300), optional `Author` (≤ 200), `Details` (≤ 500, free-form publication data) and `Url` (absolute http(s), ≤ 2048). It holds what every citation shares; the place inside the work (page, hadith number, sura:ayah) is the citation's `Locator` (≤ 200, optional). An `OpinionSource` (`OpinionId`, `SourceId`, `Order`, `Locator`) is one citation of an opinion; an opinion may cite one source several times. Any opinion may cite, a plain paragraph's included (sources are not tied to schools). Citations travel on the content DTOs as `opinions[].sources: [{ sourceId, locator }]` (list order = order, full replace like the rest; every write path, `/paragraph` too) and the read-only `ArticleContentDto.sources` lists each cited entry once, in the order of first citation. An unknown id is rejected (`source_not_found`), not dropped. A cited entry cannot be deleted (`source_in_use`, FK `Restrict`); citations go with their opinion (cascade). A second entry of the same kind, title and author (ignoring case) is refused with `source_duplicate` — a check in `SourceService`, not a database constraint. Entries are not versioned and not localized (one title as typed), and are not in the full-text search (`SearchVector` is unchanged). Authors and admins read and add entries (`CanEditArticles`); only admins edit or delete one (`CanEditAnyArticle`), because an edit shows in every article citing it. Rules live in `OpinionCitations` and `SourceService`; error codes `source_*`.
- `Article.Status` (`ArticleStatus`): `Draft → InReview → Published → Archived`. Allowed moves live only in `ArticleStatusTransitions` (Draft→InReview, InReview→Published/Draft, Published→Archived, Archived→Draft), changed via `POST /articles/{id}/status`: a reviewer (`CanReviewArticles`, Admin) makes any move, an author only `ArticleStatusTransitions.IsAuthorMove` on their own article (submit a draft for review, take it back), and `allowedTransitions` on the admin read is already narrowed to what the caller may do. New articles are `Draft`.
- Anonymous readers see only `Published` (`ArticleVisibility`): non-Published articles answer 404, related links to them are dropped, and the public tree hides a non-Published article together with its subtree. Admins see every status (badge in the tree, status panel in the editor).
- `Article` dates and authorship (M-03): `CreatedAt`, `UpdatedAt` (any content/metadata/authorship save; not status changes), `PublishedAt` (first move to Published; kept through archiving and re-publishing) — UTC, set through the injected `TimeProvider`. `AuthorId` = creating user (nullable, SetNull on user delete); co-authors via `ArticleCoAuthor` (ArticleId, UserId), never the author; admin API `GET/PUT /articles/{id}/authors`, users list `GET /users`. Readers get the dates and, on the content reads (`GET /articles/{id}/content` and by slug), a read-only `authors` list (P-06, #94): the author first, then the co-authors by user id, each `{ displayName, slug }` — no id, no email. Only users with a display name are listed (nobody named → an empty list), and `slug` is set only when the author page answers (the user is credited on a Published article), so an admin previewing a draft whose author has nothing published gets the name without a link target. It is null in the answer to a save and is not in revision snapshots. Emails stay admin-only.
- `ArticleRevision` (M-04): append-only history. Every save through `POST /articles/content` / `PUT /articles/{id}/content` writes, in the same transaction, revision N+1 (`Number` per article, `AuthorId`, optional `Comment` from the DTO's write-only `editComment`, `Snapshot` = jsonb of `ArticleSnapshotDto` — `schemaVersion` 3, self-contained: title/slug/summary/tags (as names; a restore resolves them to tags by name, creating any that are gone)/infobox/paragraphs/opinions/school ids/related links with title+slug at save time, SEO fields; version 1 has no `seo` and stays readable — restoring it clears the SEO overrides; version 3 adds each opinion's citations with a copy of the source entry as it was — kind, title, author, details, url — so versions 1–2 have none and a revision reads the same after the entry is edited or deleted; a restore re-links the citations by source id to the directory as it is now and leaves out those whose entry was deleted since). The current tables stay the working copy. Revisions are never updated or deleted; rollback (`POST /articles/{id}/revisions/{n}/restore`) saves the old snapshot as a new revision. Admin API: `GET /articles/{id}/revisions`, `/revisions/{n}`, `/revisions/compare?from=&to=`; diff is rendered client-side (`pages/article-history/revisionDiff.ts`), UI in the editor's history dialog (E-13) and on the page `/admin/articles/{id}/history`. Authors and admins alike, for the articles they may edit (`CanEditArticles` + the per-article edit check). The `AddArticleRevisions` migration backfills revision 1 for existing articles in SQL — keep its JSON shape in step with `ArticleSnapshotDto`. `Article.PublishedRevisionId` is set to the latest revision on every move to Published: the hook for D4 (#20), readers are still served the working copy. Paragraph endpoints, `POST/PUT /articles` metadata and authorship changes do not write revisions.
- Article SEO fields (M-10, #28): `SeoTitle` (≤ 70), `SeoDescription` (≤ 160), `SocialImageUrl` (absolute http(s) URL or site-relative `/path`, ≤ 2048; no upload), `NoIndex` — written as `seo` on the content DTOs (full replace like the other fields: `seo: null` clears them), validated in `ArticleSeo` (codes `article_seo_title_too_long`, `article_seo_description_too_long`, `article_social_image_url_invalid`; client mirror `src/shared/seo.ts`). Read-only `meta` on `ArticleContentDto` carries the effective values: title = SeoTitle ?? Title; description = SeoDescription ?? Summary ?? plain text of the first paragraph's default opinion cut to 160 chars on a word boundary (null if none). The article page renders `<title>`, description, Open Graph, canonical (`/{slug}`) and robots noindex through React 19 document metadata (`components/article/ArticleMeta.tsx`) — a client-side stopgap until SSR (O-01 #52, O-04 #55).
- Search (R-10, #46): PostgreSQL full-text search, `russian` configuration. The index lives only in the database (migration `AddArticleSearch`), not in the EF model: stored generated `tsvector` columns `"Articles"."SearchVector"` (title weight A; summary and tags B — the tags are read from `"Articles"."Tags"`, the search copy of the tag names that `ArticleTagAssigner` and `TagService` rewrite with every change of an article's tags, a rename or a merge, M-06) and `"Opinions"."SearchVector"` (opinion text D, Markdown/HTML reduced to text by the SQL function `mktba_search_plain_text`), a GIN index on each, the aggregate `mktba_tsvector_agg`; ё is folded to е in the vectors and the query. PostgreSQL keeps the columns current on every write path, so no code maintains the index — but changing what is indexed means a migration that re-creates the generated column. `ArticleSearchRepository` (raw SQL, PostgreSQL only) finds candidates by any query word through the indexes, then requires every word (`plainto_tsquery`, operators in the query are just text) in the article's vectors put together, so words may be spread over the title and several opinions; ranking is `ts_rank`. Results are the same for every caller: Published with every ancestor Published (a recursive CTE, the navigation tree's rule), one `locale`. Highlighting is `ts_headline` with private-use marker characters that `ArticleSearchService.ParseSegments` turns into `{ text, match }` runs — the API never returns markup and the UI renders the runs as text (`<mark>`). Limits: query 2–200 characters (`search_query_too_short` / `search_query_too_long`), `pageSize` ≤ 50, `page` ≤ 100. Tests that need PostgreSQL use `PostgresDatabaseFixture` (Mktba.Application.Tests; server from `MKTBA_TEST_DB_CONNECTION`, default the compose `postgres`); the InMemory API tests cannot run the search itself.
- `NavigationTree` exposes the article hierarchy for the sidebar.
- `User` (ex-`AdminUser`) authenticates via JWT; `Role` is `Reader`/`Author`/`Scholar`/`Admin` (stored by name, read from the DB on every request). Endpoints name a policy from `Mktba.Api/Infrastructure/Policies.cs`, never a role; `EndpointAuthorizationMatrixTests` lists every endpoint's policy. The first user is `Admin`; everyone else registers with an `Invite` (U-04 #32): a DB row with the SHA-256 hash of a random token (raw token shown once), a `Role`, `ExpiresAtUtc` (default `Auth:InviteTokenLifetimeHours`, max 720 h), optional `Note`, single-use — `UsedAtUtc`/`RevokedAtUtc` are EF concurrency tokens, so the use is a conditional update in the same SaveChanges as the new user and a racing second use fails with `invite_used`. Admins change roles via `PUT /users/{id}/role`; the last admin cannot be demoted (`last_admin_demotion`). Per-object rights for authors: U-02 #30. Frontend mirror: `src/auth/roleAccess.ts`, `useCurrentUser` (`GET /auth/me`).
- User profile (U-07, #72): nullable columns on `User` — `DisplayName` (one line, ≤ 100), `Slug` (≤ 80, unique index), `AvatarUrl` (validated like `SocialImageUrl`; no upload until U-08 #73), `Bio` (plain text, ≤ 1000), `Degree` (≤ 150), `Institution` (≤ 200) — plus `UserLink(UserId, Order, Label ≤ 60, Url)`: at most 5 labelled absolute http(s) links. Every field is optional and existing users start empty; rules in `UserProfileRules` (codes `profile_*`), client mirror `src/shared/profile.ts`. A user without a display name is shown nowhere in public — nothing falls back to the email. The slug follows `ArticleSlugRules` (same transliteration and shape, fallback word `author`): it exists exactly when the name does, a blank slug on save keeps the current one or is derived from the name the first time (`name`, `name-2`, …), and a changed slug is **not** kept — no redirects, the old address answers 404. `Degree`/`Institution` are self-declared, stored for any role and given to readers only while the role is `Scholar`; a confirmed degree belongs to the verification epic (V-01 #117, V-02 #118). A profile is public (`GET /authors/{slug}`, `PublicProfileDto`: no id, no email) only when the user has a display name **and** is the author or a co-author of at least one Published article; otherwise 404 `author_not_found`, so the endpoint cannot list accounts. `UserProfileDto.isPublic` tells the owner which it is. Links are the user's own text: render them with `rel="nofollow noopener"`, the bio as plain text. UI: `/admin/profile` («Мой профиль», any signed-in role) — the minimal form; the public author page is P-01 #89, the author line on the article P-06 #94, notification settings and the rest of profile editing P-05 #93.
- `FeedbackMessage` (F-02, #67): one anonymous message — `Type` (`ArticleError`/`SiteProblem`/`Idea`, stored by name, values start at 1), `Text` (≤ 4000), optional `Contact` (≤ 200), `PageUrl` (absolute http(s) or site-relative, ≤ 2048), `ArticleId` (SetNull on article delete), `Mazhab` (system school slug), `CreatedAtUtc`. The row is also the delivery queue: `DeliveryState` (`Pending` → `Delivered` | `Failed`), `Attempts` (EF concurrency token: an attempt starts by incrementing it, so two workers cannot take one row), `NextAttemptAtUtc`, `LastAttemptAtUtc`, `LastError` (status code and GitHub's message, never a key or token), `DeliveredAtUtc`, `GitHubIssueNumber`/`GitHubIssueUrl`, `DeliveryKey` (random guid, the hidden `<!-- mktba-feedback:… -->` marker in the issue body). `FeedbackService` validates and stores (control characters and unpaired surrogates are stripped; an unknown article id or mazhab is dropped, not an error); `FeedbackDeliveryWorker` (hosted service in `Mktba.Api/Infrastructure`, every `Feedback:Delivery:PollIntervalSeconds`) runs `FeedbackDeliveryService`, which files the issue through `IFeedbackIssueTracker` = `GitHubIssueClient` (GitHub App: RS256 JWT from the private key → installation of the repository → installation token cached until 5 min before expiry → `POST /repos/{owner}/{repo}/issues` with labels `feedback`, `needs-triage`). Decision D9 (#37): the issue (format in `FeedbackIssueFormatter`) carries type, text, page, the article title only if Published, the mazhab name and «контакт оставлен / не оставлен» with the message number — never the contact; IP and User-Agent are not stored at all. Failures: anything that is not about the message (network, 5xx, 429, 401/403/404/410, unreadable key, a 422 naming `labels`) leaves it `Pending` with a doubling delay (`RetryBaseSeconds` … `RetryMaxSeconds`), no attempt limit, and ends the run; a 422 on the issue itself → `Failed`. From the second attempt on the repository's issues changed since the message arrived (at most 300) are searched for the marker first, so an attempt cut off after GitHub created the issue does not create a second one. Not configured (`Feedback:GitHub`: `Enabled`, `AppId`, `Owner`, `Repository` and `PrivateKeyPath` or `PrivateKey`; the committed settings have no key) → the worker does not start and messages stay `Pending` with zero attempts; they are delivered once the app is configured. Tests never reach GitHub: `MktbaApiFactory` replaces the tracker, the e2e API runs with `Feedback__GitHub__Enabled=false`. Not there yet: the form (F-01 #66), the admin list (F-04 #163).
- Feedback protection (F-03, #68). Intake: `RateLimiting:Feedback` (5 / 600 s per client IP → 429 `too_many_requests`); `Feedback:Intake:MaxPerHour` (30; 0 = off) caps stored messages from everyone in any 60 minutes → 429 `feedback_limit_reached` (`TooManyRequestsException`, `Retry-After`), counted from the table itself (the N-th newest row by id), so it survives restarts and is not used up by trapped or invalid requests. Trap field `website` on `FeedbackCreateDto`: anything but white space → `FeedbackService` answers 202 with the next free number before any validation and stores nothing (one log line, no details); the form (#66) must render it hidden (`tabindex="-1"`, `autocomplete="off"`, `aria-hidden`, CSS) and send it as is. `Feedback:SiteUrl` (empty by default): when set, an absolute `pageUrl` on another origin is dropped, the message kept; site-relative paths always pass. The IP only keys the limiter's in-memory window — never stored, never logged with a message (D9). Issue body (`FeedbackIssueFormatter`, the only place visitor text becomes Markdown): the text is a fenced code block with a fence longer than any backtick run in it, `pageUrl` / article title / mazhab name are code spans built the same way, so nothing a visitor writes is parsed (no mentions, `#123` / `owner/repo#1` / SHA / issue-URL cross-links, images, links, HTML, headings) and it cannot leave the block or forge the marker; bidi overrides and isolates are stripped; `EndsWithMarker` — the marker counts only as the last line of an issue (`GitHubIssueClient.FindByMarkerAsync`). Any new visitor-controlled field must go through `CodeSpan`/`CodeBlock`. The issue title carries the published article's title as is (authors' text, not the visitor's). Client IP behind a proxy: `ForwardedHeaders:KnownProxies` / `KnownNetworks` / `ForwardLimit` (`ForwardedHeadersSetup`, first in the pipeline; empty = `X-Forwarded-For` ignored, as before) — it serves every per-IP limit, not only feedback. Tests: `MktbaApiFactory` runs with generous feedback limits; `FeedbackProtectionEndpointTests` start their own API per test.

**API surface** (all in `Mktba.Api/Endpoints/`):
- `/auth` — `GET /status`, `POST /register` (first admin, then only with an invite token; the user gets the invite's role), `POST /login`, `POST /refresh`, `POST /logout`, `POST /logout-all`, `GET /sessions`, `DELETE /sessions/{id}`, `GET /me`
- `/invites` — `GET /`, `POST /` (role, lifetime, note → token once), `POST /{id}/revoke` (Admin only)
- `/users` — `GET /` (with roles and display names), `PUT /{id}/role`, `GET|PUT /{id}/profile` (Admin only)
- `/profile` — `GET /`, `PUT /` (the signed-in user's own profile, a full replace; any role)
- `/authors/{slug}` — the public profile; 404 unless the user has a display name and is credited on a Published article
- `/authors/{slug}/articles?locale=&page=&pageSize=` — the author's articles a reader can open (P-01, #89): written or co-authored, Published with every ancestor Published, no empty stubs, by `PublishedAt` newest first; `AuthorArticlesDto { total, page, pageSize, items }`, page size 20 by default and at most 50; the same 404 as the profile (`AuthorArticlesService`, sharing `ArticleReachability` with `RecentArticlesService`). The list may be empty for a public author: a profile is public by any Published article
- `/navigationTree/tree` — article hierarchy for the sidebar
- `/articles` — article CRUD (`GET /`, `GET /{id}`, `POST /`, `PUT /{id}`, `DELETE /{id}`)
- `/articles/{id}/content`, `POST /articles/content` — article with its paragraphs and opinions, read and saved as a whole
- `/articles/by-slug/{slug}/content` — the same content by slug; an old slug answers 302 to the current slug's URL
- `/articles/recent?locale=&limit=` — the home page's lists (R-05, #41): `new` by `PublishedAt`, `updated` = saved after publication, by `UpdatedAt`; public, the same for every caller: Published, every ancestor Published, no empty stubs (`RecentArticlesService`)
- `/search?q=&locale=&page=&pageSize=` — full-text search (R-10, #46), public; items carry `title` / `summary` / `snippet` as `{ text, match }` runs and the snippet's `paragraphId`
- `/paragraph` — paragraph CRUD (`GET /`, `GET /{id}`, `POST /`, `PUT /{id}`, `DELETE /{id}`)
- `/schools` — `GET /system`, `GET /article/{articleId}`, `POST /`, `DELETE /{id}`
- `/sources` — `GET /?q=&kind=&limit=` (the directory, for the editor's picker), `POST /` — authors and admins; `PUT /{id}`, `DELETE /{id}` (refused while cited) — admins
- `/tags` — `GET /tags/{slug}?locale=&page=&pageSize=` (M-06, #70), public: `TagPageDto { name, slug, total, page, pageSize, items }`, the items as on the author page (Published, every ancestor Published, no empty stubs, newest publication first); 404 `tag_not_found` when the locale has no such tag or no such article carries it. Admins: `GET /?locale=` (every tag with `articleCount`), `PUT /{id}` (`{ name, slug? }` rename), `POST /{id}/merge` (`{ intoTagId }`)
- `/feedback` — `POST /` (F-02, #67), public: `{ type, text, contact?, pageUrl?, articleId?, mazhab? }` → `202 { id }` once the message is stored; the GitHub issue is created in the background, so the answer does not depend on GitHub. Errors: `feedback_type_invalid`, `feedback_text_required`, `feedback_text_too_long`, `feedback_contact_too_long`, `feedback_page_url_invalid`; 429 `too_many_requests` (per client) and `feedback_limit_reached` (all visitors, per hour), both with `Retry-After`. Optional `website` is the trap field for bots (F-03, #68): filled in → 202 and nothing stored
- `/admin` — `POST /cleanup`, `GET|PUT|DELETE /ai-settings`, `POST /ai-style`, `POST /ai-check`

**Frontend rendering (O-01, decision D1):**
- React Router v7 framework mode, `appDirectory: 'src'`: `src/root.tsx` (document, providers), `src/routes.ts` (route config), `src/routes/*` (route modules), `src/entry.client.tsx` (browser startup: session restore, Metrika).
- Public routes have a server `loader` that fetches the API anonymously (`src/server/api.server.ts`, base `API_INTERNAL_URL`) into a server QueryClient and returns `dehydrate()`d state; the route component wraps the page in `HydrationBoundary`. A `clientLoader` skips the server on later client-side navigations (pages fetch through React Query as before). Loaders set status codes (`data(..., { status: 404 })`, `redirect(..., 301)`). Under the block a hint names the uncovered schools and says their readers get the default opinion. Everything changes `ArticleDraft.blocks` only (dirty check, local copy). Not there: removing a school by an `×` on its tab (the chips do it), reordering opinions.
- Reader preview (E-11, #81): the toolbar's «Просмотр» opens `ArticleDraftPreview` (`pages/add-article/`) as a modal dialog over the whole window (`PreviewDialog`: portal into `body`, the focus on its close button, Escape — also from inside the frame — or the button closes it and the focus returns to «Просмотр»; meanwhile the page's other `body` children are `inert` + `aria-hidden` and the body does not scroll), with the mazhab and width switches in its top bar and the editor left mounted behind it: the unsaved draft through the reader's own components — breadcrumbs (from the editor's tree: the parent picker's path for a new article), h1, `ArticleDates` (the saved article's dates and authors; reading time from the draft), `ArticleMobileOverview`, infobox, the text and the footer's sources, child and related articles (no previous / next: the draft's place is not final), and from `xl` the right sidebar. `buildArticlePreviewContent` (`articlePreview.ts`) turns the draft into paragraphs the way a save would store them (`buildParagraphUpdateDtosFromBlocks`: empty blocks dropped, a block left with one text is a plain paragraph), numbered by position. Paragraphs go through the same code as `ArticlePage`: `useRenderedParagraphs` / `useArticleOutline` / `useTocItems` (`components/article/useArticleParagraphs.ts`) and `ArticleParagraphList` (`ArticleParagraphs.tsx`, plain paragraphs and `VersionedParagraphBlock`). The preview's mazhab is its own state, started from `useMazhab()` and never written back, so `localStorage['mktba.mazhab']` and the reader's choice stay as they were. The width switch (phone 375 / tablet 768 / desktop 1280, `PREVIEW_WIDTHS`) renders the column in an iframe of that width through a portal (`PreviewFrame`: the page's stylesheets are copied into the frame once it is attached, React context is kept), so the viewport breakpoints `sm:`…`xl:` and the infobox's `@container` respond as on that screen. The frame fills the dialog; desktop 1280 is at full size (`data-scale="1"`) on a window of about 1312px and wider and scaled down only below that. Not emulated: the site header, the left navigation (its width is kept empty from `lg`), the phone's bottom mazhab bar, touch, the device's pixel ratio and fonts. The frame is `box-content`, so its border does not narrow the emulated viewport. Links inside the preview never navigate; an `#anchor` scrolls the frame. `e2e/preview.spec.ts` checks the frame in a real browser (dialog and focus, scale 1 at a 1440px window, styles applied, mazhab switch, `innerWidth` 1280 and 375, Escape closes, saved mazhab untouched). Stylesheets added to the page after the frame attached (a lazily loaded route's CSS in dev) are not copied.
- Internal links (E-10, #80): an internal link is site-relative Markdown pointing at an article, `[text](/{slug})` (query and fragment allowed, `[text][ref]` with `[ref]: /{slug}` too) — what `internalArticleSlug` in `pages/add-article/internalLinks.ts` accepts: one path segment, not a reserved route, no dot. The bottom toolbar's «Ссылка на статью» opens `InternalLinkDialog`, which filters the editor's navigation tree (every article the user may see, any status, by title, path or slug; Enter takes the first) and knows nothing about the text being edited: the page inserts the link into the text that was active when the picker opened — in a paragraph or an opinion through the rich text's handle (`RichTextHandle.insertArticleLink`: the selection, or the title, becomes the link text, `articleHref(slug)` the target, the link text selected afterwards), in a heading's textarea through `insertArticleLink` (`markdownFormat.ts`, committed with `flushSync` and the selection restored in the same event, so a key pressed right after it lands where the user put the caret). «Внешняя ссылка» is the external link (E-04). `findBrokenInternalLinks` (mdast parse of every opinion, each slug once per block) runs on every change once the tree is loaded and `InternalLinkWarnings` lists, under the document (all widths), links whose slug is no article the tree holds (`missing` — mistyped, deleted, or an old slug: it still redirects, but the warning asks to update it, since old slugs are not in the tree) and links to a non-Published article (`unpublished` — readers get 404), each with a jump to its block. A warning only: saving is never blocked. For an author the tree holds only what they may see, so a link to someone else's unpublished article counts as missing. On the reader page (and the preview) `MarkdownContent` renders any site-relative link as a router `Link` in the same tab; external links still open a new tab. Not checked: absolute links to the site's own domain, links in the summary or infobox.
- Infobox layout (R-04): `ArticleInfoboxPanel` floats right by the width of its nearest `@container` ancestor (`@2xl`, the article column), not the viewport; whatever renders it must provide that `@container flow-root` wrapper. A bordered or filled block that can sit next to it needs `flow-root` so it ends at the float instead of running under it. Below `sm` the body is collapsed with CSS only (it stays in the server HTML).
- Empty and loading states (R-14, #49): the server HTML is complete, so placeholders show only on client-side loads. `src/components/Skeleton.tsx` holds `SkeletonBar` (grey bar, `aria-hidden`, no pulse under `prefers-reduced-motion`), `LoadingPlaceholder` (`role="status"` with «Загрузка...» for screen readers) and `NavigationTreeSkeleton` (the sidebar and the admin tree while the tree loads); `components/article/ArticleSkeleton.tsx` stands in for the article column. An empty tree says so (no published articles; in the admin, no articles), and a sidebar filter that matches no title says so and links to the full-text search for the same words when the query is searchable. No block shows an empty shell: a stub has no table of contents, the right sidebar leaves out every empty block (no «Связанных статей нет» placeholder) and is not rendered at all when all of them are empty; the footer already leaves out its empty blocks (R-08). Admin lists and editors still use the spinner or «Загрузка...» text.

**Frontend ↔ Backend:**
- Base URL configured in `mktba.react/src/config.ts` (`http://localhost:5172`)
- CORS allows any loopback / `localhost` origin (Vite dev port `:5173`)
- Access token (15 min) kept in memory only (`src/services/session.ts`); the refresh token is an `httpOnly` cookie (`mktba_refresh`, `Path=/auth`) rotated by `POST /auth/refresh`, which the axios interceptor calls once on a 401 and the app calls on load. Access tokens carry the session id (`mktba_sid`) and `JwtProblemEvents.TokenValidated` rejects them once the session is revoked (README «Сессии»). Protected routes under `/admin/*`
- HTTP via Axios; server state via React Query
- Global mazhab selection stored in `localStorage['mktba.mazhab']`, exposed through `MazhabContext`; the picker (`components/mazhab/MazhabSelector.tsx`) sits in the public header (on phones in the bottom bar, R-11) and shows a one-time hint (`localStorage['mktba.mazhabHintSeen']`). A shared link `?mazhab=<system school slug>` (R-03, #39) wins over the saved choice while the parameter is in the URL and never overwrites it; choosing by hand saves the choice and drops the parameter. The canonical schools are prefetched by the public layout's loader (`routes/public-layout.tsx`), not by pages: a query a component above a page's `HydrationBoundary` already observes gets that boundary's data only in an effect, too late for the server HTML — for the same reason `MazhabProvider` (above the layout) resolves the link slug through a query key of its own
- Yandex Metrika (N-01, #51): `src/analytics/metrika.ts`. The counter starts only with `VITE_METRIKA_ID` set at build time **and** the visitor's consent (`localStorage['mktba.consent']`, `CookieConsent`): `entry.client.tsx` on load, or the consent banner. Without either every call is a no-op (tests, e2e, declined visitors). `init` counts the page a visit starts on; `usePageViewTracking` (the root's `PageViewTracker`) sends a `hit` with the previous page as `referer` on every later client-side navigation to another page — a change of path or query, not of the hash (anchors, the table of contents) and not of `?mazhab=` (dropped from the URL after a choice). Goals are `METRIKA_GOALS`, the only place their ids live; they are set up in the counter by these ids, so never rename one: `article_view` / `article_time_5min` (an article opened / still open after 5 min, `{ articleId }`), `article_read_end` (the end of the text came into view, once per article opened, never for a stub, `{ articleId }`, `useReadToEnd`), `opinion_switch` (`{ paragraphId, index }`), `mazhab_change` (chosen by hand in the picker, `{ schoolId }`), `search` (a submitted `SearchForm`: the home page, the results page, the Ctrl+K dialog; no query text — the hit's URL carries it), `toc_click` (an entry of the right sidebar's table of contents, `{ depth }`). Goal params never carry personal data.

**Database:** PostgreSQL 16. Connection string `ConnectionStrings:DefaultConnection`; Development uses `appsettings.Development.json`, matching `docker-compose.yml` (service `postgres`).

**Migrations and seeding (X-03, #65):** `DatabaseStartup` (`Mktba.Api/Infrastructure`) runs before serving: with `Database:MigrateOnStartup` (true only in `appsettings.Development.json`, which the e2e API uses) it calls `DatabaseMigrator.MigrateAsync` (`Mktba.Infrastructure/Data`: migrations, then `SystemSchoolSeeder` — the 4 canonical schools with their English names, reference data needed in every environment); otherwise `DatabaseMigrator.EnsureUpToDateAsync` only checks and the API refuses to start while a migration is pending. Outside Development migrations are applied by the same binary run with `--migrate` (migrate, seed, exit; idempotent) — the step a deployment (X-02 #64) runs before the new version. The InMemory provider of the API tests is always created and seeded. There is no demo data in the API: demo content comes only from `scripts/seed-demo-content.mjs` through the API.

## Coding conventions

- English for all code symbols; Russian may appear in UI strings/comments/AI prompts.
- UI text lives only in `mktba.react/src/localization/locales/ru/*.json`; ESLint (`i18next/no-literal-string`) fails on hard-coded JSX text and user-facing attribute strings in `src/**/*.tsx`.
- No dead code, no commented-out blocks, no TODOs without an issue reference.
- No unrelated refactors mixed into task-specific changes.
- Keep public API/DTO contracts documented.
- API errors are `application/problem+json` bodies (`ApiProblemDetails`: `title`, `status`, `code`, optional `params`, `traceId`). Add a new error to `Mktba.Application/Exceptions/AppErrors.cs` (stable snake_case code) and its Russian text to `apiErrors` in `mktba.react/src/localization/locales/ru/shared.json`; the UI shows only the translation by code, never the server's `title`.

## Testing

- Unit tests for domain logic; integration tests for DB/API boundaries.
- Prefer real behavior over mocks. Assert observable outcomes.
- Test names: describe scenario + expected result (Given/When/Then structure).
- Cover happy path, at least one edge case, and one failure path per behavior change.
- For bug fixes, add a regression test.
