# mktba — бэклог

Составлен по результатам аудита от 2026-09-01: поднято локальное окружение
(Postgres 16 в docker, `Mktba.Api` на :5172, Vite на :5173), в чистую БД залит
демо-контент из 6 статей (4 столпа + вложенная «Джума-намаз» + пустая
статья-заглушка «Хадж»), с мнениями по всем четырём мазхабам и одной кастомной
школой со скоупом статьи. Проверены: дерево слева, страница статьи,
страница-заглушка, поиск, мобильная вёрстка, все вкладки админки,
редактор создания и редактор правки.

**Обновлено после мержа `claude/cool-cannon-7c4167`** (итерации 4–8, шесть коммитов,
лежали в worktree незалитыми). Ветка закрыла весь P0 и два пункта P1 — отмечено ниже.
Пункты с пометкой «⟳ перепроверено» проверены заново на смёрженном main;
остальные перенесены из аудита как есть.

Статус помечать прямо здесь: `[ ]` → `[x]`.

## P1 — крупные функциональные дыры

- [ ] **A1. Статью-заглушку нельзя наполнить.** ⟳ перепроверено
  `NavigationTree.tsx:32`: `isClickable = article.hasContent`. Заглушка некликабельна
  и в публичном, и в админском режиме. Создать пустую статью можно
  (`POST /articles`, кнопка «Добавить статью»), а попасть в её редактор — нельзя.

- [ ] **A2. В админке нет списка статей.**
  Вкладка «Статьи» — дашборд: три счётчика и топ-5 по числу абзацев.
  Нет списка всех статей, поиска, фильтров, пагинации. Единственный путь
  к редактору — дерево в левом сайдбаре.

- [x] **A3. Удаления статьи нет в UI.**
  Кнопка «Удалить» появилась в редакторе статьи. → `39c5a51`

- [x] **A4. Управления кастомными школами нет в UI.**
  Панель «Кастомные школы» с кнопкой «Добавить школу» появилась в редакторе;
  `schoolService.ts` покрывает `POST /schools` и `DELETE /schools/{id}`. → `09cb3b9`

- [ ] **A5. Дерево нередактируемо.** Нет перетаскивания, смены порядка, смены родителя,
  переименования, добавления дочерней статьи из узла.

- [ ] **A6. Состояние раскрытия дерева не сохраняется.**
  `useState(true)` в `NavigationItem` — все узлы всегда раскрыты, состояние теряется
  при перемонтировании. На дереве в сотни статей это неуправляемо.

- [ ] **A7. Поиск только по заголовкам.**
  Запрос «молитв» не находит «Салат», хотя слово есть в кратком описании.
  Нет поиска по контенту, тегам и мнениям; нет подсветки совпадений;
  при нуле результатов дерево просто пустеет без сообщения.

- [ ] **A8. Нет 404-маршрута.** ⟳ перепроверено
  В `App.tsx` пять маршрутов и ни одного catch-all. Любой неизвестный URL —
  например `/admin/articles/new` — рендерит пустую страницу внутри layout.

- [ ] **A9. Маршрут создания статьи вне admin-неймспейса.** ⟳ перепроверено
  `App.tsx:61` — `/article/new` соседствует с публичным `/article/:id`,
  тогда как правка живёт на `/admin/articles/:id/edit`.

  `This action is permanent and cannot be undone.` (:609).
  Плюс английские значения внутри самих ru-локалей: в `editor.json` остались
  `Heading H2`, `Heading H3`, `Paragraph` (ключ `versioned` уже переведён),
  в `pages.json` — 12 строк.

- [x] **L2. Демо-текст из английской Википедии в настройках.**
  Вкладка «Интерфейс» удалена целиком вместе с плейсхолдером. Решение верное:

  `Slot at order 1 must have at least one opinion.`,
  `Order values must form a contiguous sequence from 1 to N.` — показываются в русском тосте.

- [ ] **L4. Бейдж «Published» вводит в заблуждение.**
  В доменной модели нет статуса публикации; это `hasContent ? 'Published' : 'Placeholder'`.

- [ ] **N1. Обычный абзац молча теряет привязку к школам при сохранении.** ⟳ найдено после мержа
  Round-trip через UI на статье «Салат»: у первого (не версионного) абзаца
  `schoolIds` изменился с `[1,2,3,4]` на `[]`. Версионные блоки свои связи сохраняют.
  Похоже на осознанное поведение — «обычный абзац общий для всех школ», — но сейчас
  это побочный эффект отсутствия чипов у не-версионных блоков, а не явное решение.
  Определиться: либо не отправлять школы для таких абзацев намеренно и задокументировать,
  либо сохранять исходные связи.

- [ ] **U1. Инфобокс перекрывает версионный блок в редакторе.**
  Карточка «Обзор / Краткая справка» ложится поверх шапки версионного блока

- [ ] **U4. На мобильном теряются бренд и весь правый сайдбар.**
  В шапке нет «mktba», только иконки. Краткое описание, теги и оглавление

- [ ] **U5. Публичный сайдбар и поиск видны на страницах админки** (вход, дашборд) —

## Что работает — не переделывать

- Доменная модель «параграф → мнение → мазхаб» реализована сквозь весь стек:
  бэкенд создаёт и отдаёт мнения со связями, фронт их рендерит, глобальный выбор

  мнение по умолчанию на слот, проверка принадлежности id статье, всё в транзакции.
- Бутстрап первого администратора и поток invite-token работают.
- «Опасная зона» защищена вводом фразы `DELETE DEMO DATA`, а не одной кнопкой.
- Редактор статьи: блоки, инфобокс, теги, связанные статьи, кастомные школы,
  импорт Markdown, ИИ-стилизация, предпросмотр, счётчики.
- `rehype-sanitize` подключён к рендеру markdown. ESLint чистый, сборка без ошибок,
  44 бэкенд-теста зелёные.

## Как воспроизвести окружение аудита

```bash
docker compose up -d postgres
```

API против отдельной демо-БД (основная `mktba` не трогается):

```bash
ConnectionStrings__DefaultConnection="Host=localhost;Port=5432;Database=mktba_demo;Username=mktba;Password=mktba_dev" ASPNETCORE_ENVIRONMENT=Development dotnet run --project Mktba.Api --urls http://localhost:5172
```

Фронтенд:

```bash
npm --prefix mktba.react run dev
```

Демо-контент (нужен токен админа):

```bash
node scripts/seed-demo-content.mjs --email admin@mktba.local --password '<пароль>'
```

Админ демо-БД: `admin@mktba.local` / `MktbaDev12345!` (создан через штатный
bootstrap-флоу, только для локальной `mktba_demo`).
